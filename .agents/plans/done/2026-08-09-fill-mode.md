# hexagons: режим `fill` — «мятый кристалл» по образцу trigons-lite

## Context

В hexagons-lite (W:\projects\hexagons) три поверхности — `field`, `hive`, `pattern()` — все line-art. Пользователь хочет четвёртую: **залитый** фон с входной анимацией, как в W:\Projects\trigons-lite. Выбранный стиль (AskUserQuestion): **«мятый кристалл»** — каждый шестиугольник разбит на 6 треугольников от центра, у каждого своя псевдонормаль → огранённое «драгоценное» сияние, почти как trigons, но с гексагональной топологией.

Механика trigons (изучена, `trigons-lite.js`, 235 строк, ~2 KB gz): сетка вершин с джиттером (`chaos`) → плоские заливки, цвет = диагональный 3-стопный ramp по центроиду × псевдо-освещение `(0.6, 0.4)·normal·depth`; шов антиалиасинга закрывается обводкой цветом заливки (lineWidth 0.75); входная анимация — стаггерный фронт по направлению (`fade|scale|spin|fly`, `direction: top|bottom|left|right|center|random`, `duration`, `stagger`, cubic easing), после завершения rAF полностью останавливается — дальше статичная картина. Известные слабости trigons, которые НЕ переносим: нет DPR, нет destroy(), утечка resize-листенеров, ре-рандомизация меша при каждом resize.

## Изменения

### 1. `hexagons.js` — mode `'fill'`

**Меш** (новая `buildFill()`, рядом с `buildHive()`):
- Решётка вершин hive (переиспользовать константы pointy-top + flat-swap как в `buildHive`); каждая **общая** вершина джиттерится один раз на `±size·chaos/2` — детерминированно через существующий `hash(i,j,d)` (не `Math.random`): меш водонепроницаем и **стабилен при resize** (фикс слабости trigons). Центр каждой ячейки джиттерится своим hash.
- Каждая ячейка → 6 треугольников (центр + пара соседних вершин). На 1920×1080 при size 90 ≈ 2000 треугольников — приемлемо: полный redraw только в кадрах анимации, потом статика.
- Цвет треугольника печётся при генерации (как в trigons): `t = clamp((cx/W + cy/H)/2)` → piecewise-lerp по ramp; × `sh = 1 + dot(normal, (0.6,0.4)) · depth` (формула псевдонормали trigons `:102-104`); один `rgb()`-стринг на треугольник.
- **Ramp по умолчанию — из авто-палитры**: `[background, halo, colors[0]]` (dark: L6→L12→L32 брендового hue — тёмный кристалл с брендовым свечением в правом-нижнем углу; light: L97→L92→L72). Запиненный `colors` в fill-режиме становится ramp'ом как есть (можно повторить казино-стиль `[bg, surface, accent]`).

**Анимация** (`animateFill()` внутри init):
- Порт trigons `animate()`: эффекты `fade|scale|spin|fly` (+ fallback scale-без-вращения), направления `top|bottom|left|right|center|random`, `duration` (default 1500), `stagger` (0.6), cubic `easing` (`ease-out` default). Стаггер-задержки и spin-углы печутся при генерации.
- Часы — существующий аккумулятор `t` через `frame(dt)`: **`step(dt)` работает и для fill**, seeded-прогон воспроизводим (random-direction и spin — через `rnd`, т.е. mulberry32 при `seed`).
- По завершении входа `drawFill` сам останавливает цикл (внутренний флаг + `sync()`), - ковенант «спит, когда нечего рисовать» соблюдён. IntersectionObserver уже гейтит цикл — вход на паузе вне экрана доиграет при появлении.
- `resize()`/`set()` в fill-режиме: перегенерация меша (hash-стабильная) + один синхронный статичный кадр, без replay.

**API/опции**:
- `mode: 'fill'`; новые опции `chaos` (default 0.5, fill), `depth` (0.4, fill), `animation` (объект или `null` = появиться мгновенно; fill).
- Методы handle: `animateIn(opts?)`, `animateOut(opts?)` (обратный ход, `v = 1-p`; работают в fill-режиме, в остальных no-op).
- `get()`/`set()` расширить: `chaos`/`depth` (rebuild), `animation` (хранится; replay — методом).
- Не применимы к fill и не меняются: `sweep`, `bond`, `inset`, `weight`, `glow`, `count`, `nesting`, `parallax`.

### 2. Демо `index.html`
- В select mode добавить `fill`; новая группа панели «Fill»: слайдеры chaos/depth/duration/stagger, селекты effect/direction, кнопка **replay** (`animateIn()`).
- Переключение темы при `mode === 'fill'`: `animateOut` (0.6×duration, ease-in) → `set({theme})` → `animateIn` — приём casino-platform `Layout.tsx`, красиво продаёт фичу.

## Verification
1. Гейты: `npm run lint`, `npm run build`, `npm run size` (≤ нового потолка; вписать замер в спеку/CHANGELOG).
2. Браузер (serve + Chrome, обе темы): входная волна scale/top по умолчанию; спот-чек эффектов fade/spin/fly и направлений center/random; фасеты читаются (chaos 0.5/depth 0.4); ramp тянет брендовое свечение в угол.
3. rAF-остановка: после завершения входа счётчик кадров демо-fps продолжает 60 (он свой), а канвас статичен — проверить внутренним флагом через `get()` или отсутствием изменений пикселей между двумя снятиями.
4. Детерминизм: seeded fill, `autoplay:false` + `step(1/60)` × N — два прогона попиксельно идентичны (getImageData-хэш).
5. Resize: изменить размер контейнера — узор тот же (hash-стабильность), без re-random.
6. Theme-flip в демо: out → смена палитры → in, без ошибок в консоли.
7. Uborka: закрыть вкладку, убить сервер; коммит с гейтами.
